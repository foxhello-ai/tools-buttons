## 目标与职责

1. 按钮可声明参数，由项目脚本动态提供目录、worktree、分支、环境等候选项。
2. 用户停止任务后，可点击指定节点，从该节点继续后续流程，复用仍有效的前置结果。
3. 保留每次执行的输入、日志、节点、产物和续跑关联，不能覆盖旧历史。
4. 保留普通按钮及当前“点击节点筛选日志”的行为。

| 职责 | 应用 | 项目脚本 |
| --- | --- | --- |
| 参数 | 根据 JSON 生成控件，调用声明的选项命令，固定确认结果 | 枚举 worktree、分支、目录和环境，返回候选数据 |
| 预览 | 展示脚本返回的通用摘要和是否可执行 | 校验参数、提交、修改状态、环境、检查点和产物 |
| 执行 | 启动配置命令、传递参数和上下文、取消进程、收集事件 | 切换目录或分支、决定步骤顺序、执行或恢复业务 |
| 续跑 | 提供节点入口、建立新任务、保存父子记录 | 判断哪些步骤可复用、从何处继续、失败时如何处理 |
| 发布保护 | 保留固定参数及通用任务并发限制 | 固定版本、源码复核、产物校验、环境互斥、远端基线和回滚 |

应用不调用 Git、不扫描 worktree 源码、不解释项目 manifest，也不依据流程图自动调度业务命令。
脚本可以使用 Shell、Python 等语言；本文中的 Shell 入口仅为示例。

## 参数选择与确认

流程：点击动作 → 选项脚本返回 JSON → 选择参数 → 预览脚本返回摘要 → 用户确认 → 创建任务。

- 选项和预览命令约定为只读；不构建、上传、切换分支或修改远端。
- 候选项支持 `label`、JSON 类型的 `value`、通用键值 `details` 和禁用原因。应用不解释 value 内的 Git 字段。
- 选择框中可展示路径、分支、完整提交和修改状态，内容由项目脚本生成。
- 正式执行时才由脚本根据已确认参数切换目录或按需切换分支。
- 取消不创建执行任务。预览失败、过期或配置变化，要求重新预览。
- 选项错误或已选择目录不可用时显示原因，不自动替换为其他选项。

## 节点续跑交互

用户提供的四阶段示例：检查 → 构建与测试 → 部署 → 部署后检查。

停止发生在“部署”时，用户点击该节点，可查看节点日志，并选择“从此节点继续”。随后展示续跑确认：

```text
原任务：任务 A
来源：原目录 / 原分支 / 原提交
环境：原环境

检查          复用已完成结果（脚本已复核）
构建与测试    复用已有产物（脚本已校验）
部署          从此节点继续
部署后检查    将执行

[取消]  [从“部署”继续]
```

- 运行中的任务仍可筛选日志，但不能同时发起续跑；停止请求处理完、任务进入终态后才开放入口。
- 可续跑的历史状态包括取消、失败、超时及中断；首期不为成功任务提供续跑入口。
- 配置声明的候选节点可点击申请续跑，最终是否允许由预览脚本判断；不可用时显示具体原因。
- 点击节点只打开操作与预览，不直接执行命令。取消预览不产生任务。
- 选择“构建与测试”表示从该节点重新执行，并由脚本重新处理受影响的后续步骤；不能复用旧的下游成功状态。
- 选择“部署后检查”时，脚本必须确认实际已发布的版本，不能仅依据图上曾有“部署成功”就放行。
- 首期语义为“从节点继续后续流程”。节点内部的断点、上传续传及远端阶段恢复能力由项目脚本提供。
- 并行流程的前置条件、受影响分支和执行集合由脚本返回；应用不把图的视觉顺序当作执行顺序。

## 配置示例

以下字段已接入 schema、Web 和 Swift 桌面入口：

```json
{
  "id": "deploy",
  "icon": "upload",
  "tooltip": "部署",
  "parameters": [
    {
      "name": "source",
      "label": "部署来源",
      "type": "select",
      "optionsCommand": ["bash", ".project-actions/scripts/deploy.sh", "options"]
    }
  ],
  "previewCommand": ["bash", ".project-actions/scripts/deploy.sh", "preview"],
  "command": ["bash", ".project-actions/scripts/deploy.sh", "run"],
  "resume": {
    "nodes": ["check", "build", "deploy", "verify"]
  },
  "workflow": {
    "nodes": [
      {"id": "check", "label": "检查"},
      {"id": "build", "label": "构建与测试", "dependsOn": ["check"]},
      {"id": "deploy", "label": "部署", "dependsOn": ["build"]},
      {"id": "verify", "label": "部署后检查", "dependsOn": ["deploy"]}
    ]
  }
}
```

`resume.nodes` 只声明允许申请续跑的节点，不为节点配置命令，不把应用变成业务调度器。
预览和正式执行复用原有脚本入口，通过执行上下文区分首次运行与续跑。
未声明 resume 的动作维持旧行为。动态节点需显式出现在可续跑声明中，不能自动获得执行入口。

## 传参和固定输入

应用通过环境变量提供两个独立 JSON 文件：

- `PROJECT_ACTIONS_PARAMETERS_FILE`：用户确认的业务参数快照。首次运行和续跑均使用该接口。
- `PROJECT_ACTIONS_CONTEXT_FILE`：应用生成的执行上下文，业务参数不能覆盖。

参数文件示例：

```json
{
  "source": {
    "directory": "/project/finance",
    "branch": "feat/finance",
    "commit": "完整提交标识"
  },
  "environment": "staging"
}
```

续跑上下文示例：

```json
{
  "version": 1,
  "mode": "resume",
  "resume": {
    "fromNode": "deploy",
    "parentRunId": "前一次任务 ID",
    "rootRunId": "首次任务 ID",
    "parentRunDirectory": "/project/.project-actions/runs/前一次任务ID",
    "checkpoints": [
      {
        "id": "已注册的检查点 ID",
        "nodeId": "build",
        "runId": "产出检查点的任务 ID",
        "path": "/project/.project-actions/runs/产出任务ID/build-checkpoint.json"
      }
    ]
  }
}
```

- 首次运行使用 `mode: "new"`；运行阶段的上下文同时包含新任务 ID。预览阶段不预先创建执行任务。
- 父任务、根任务及检查点路径由服务根据本项目历史解析，不接受浏览器指定任意目录。
- 连续续跑时保留原始检查点的所属任务，不能假定所有可复用产物都在最近一次任务目录中。
- 续跑沿用原业务参数和动作配置；修改来源、提交、环境等参数应新建任务，不静默变为另一版本的续跑。
- 当前动作配置若与原任务不兼容，首期拒绝续跑并提示新建任务；脚本自身版本及检查点格式兼容性由脚本复核。
- 通过 JSON 传参，不拼接 Shell 命令。服务校验节点 ID、预览凭据、项目归属及重复启动。
- 参数和上下文在确认后固定；脚本按只读输入使用。文件保存快照不等于源码或业务产物已被物理锁定。

## 检查点与产物

节点状态只描述执行结果。节点变绿不能证明它的输出仍存在，也不能自动作为可恢复检查点。

已提供通用 `checkpoint` 事件及辅助函数：

```bash
# 业务脚本完成阶段、原子写入状态文件后注册。
pa_checkpoint build "$PROJECT_ACTIONS_RUN_DIR/build-checkpoint.json" --label "构建结果"
```

```json
{
  "type": "checkpoint",
  "nodeId": "build",
  "path": "/project/.project-actions/runs/本次任务ID/build-checkpoint.json",
  "label": "构建结果"
}
```

- 应用仅注册文件、检查通用路径边界、保存归属和完整性信息；不解释文件中的业务内容。
- 文件及符号链接解析后的路径须位于本次任务目录，文件先生成再注册；更新检查点应原子写入并重新注册。
- 项目脚本自行决定检查点内容，例如构建目录、提交、产物哈希、发布标识、远端操作进度及已完成阶段。
- 预览时和正式执行前，脚本都要校验检查点及对应实际产物。预览到执行之间仍可能发生变化。
- 原任务数据按历史保留。续跑需要修改状态时，在新任务目录复制并生成新检查点，不覆盖旧 manifest、日志或报告。
- 历史任务没有检查点时默认不可续跑，显示“该任务未保存可恢复结果”，不根据旧日志猜测。
- 进程突然终止、产物清理、检查点缺失或格式不兼容时，展示明确原因，由用户选择其他起点或重新运行。
- 检查点不是凭据存储接口；敏感配置不写入界面摘要、日志或结果 JSON。

## 续跑预览与执行

同一 previewCommand 读取参数和上下文，项目脚本返回通用数据：

```json
{
  "allowed": true,
  "summary": [
    {"label": "续跑起点", "value": "部署"},
    {"label": "部署环境", "value": "staging"},
    {"label": "固定提交", "value": "完整提交标识"}
  ],
  "plan": [
    {"nodeId": "check", "operation": "reuse", "checkpointId": "检查检查点ID"},
    {"nodeId": "build", "operation": "reuse", "checkpointId": "构建检查点ID"},
    {"nodeId": "deploy", "operation": "run"},
    {"nodeId": "verify", "operation": "run"}
  ]
}
```

不能继续时返回 `allowed: false` 及 `reason`，例如“构建产物已删除，需要从构建节点开始”。
应用展示建议但不擅自更改用户选择的起点。

预览结果绑定原任务、节点、参数快照、动作配置、检查点引用及计划，使用有期限的单次确认凭据。
只有用户确认后才创建新任务，并把已确认计划传给配置中的执行脚本；脚本据此执行并再次校验。

业务脚本仍负责以下事项：

1. 确认固定提交和源码是否变化，不能把相同分支名当作相同版本。
2. 校验复用产物，不能因构建节点曾成功就发布已丢失或被替换的文件。
3. 确认前次取消后远端操作是否仍在进行，取得同环境互斥并核对远端基线。
4. 按真实操作状态幂等重试或恢复，避免重复发布、重复备份、重复迁移等副作用。
5. 上报哪些节点复用、哪些节点实际执行，以及本次真实发布产物身份。

应用可终止本机进程组；这不能证明远端任务已停止。原任务已终止只是申请续跑的界面前提，
正式执行仍须由项目脚本核查远端操作和锁。应用不提供任意业务的自动回滚或远端事务保证。

## 记录与接口

以下接口已实现，均使用现有界面身份验证；不接受任意命令：

| 接口 | 用途 |
| --- | --- |
| `POST /api/runs/<id>/resume-preview`，body `{"nodeId":"deploy"}` | 从历史参数构建续跑上下文并调用该动作的预览命令；不创建任务 |
| `POST /api/runs`，body `{"actionId":"deploy","previewId":"..."}` | 消费已确认预览，创建首次运行或续跑任务 |
| 现有任务 report 接口增加 checkpoint 与结构化 result 事件 | 保存可恢复文件引用和脚本上报的实际结果 |

每次续跑生成新 runId，保存 parentRunId、rootRunId、resumeFromNode、原参数、动作配置、已确认计划与检查点引用。
日志、退出码、节点结果及产物分别保存；历史可导航到原任务和后续续跑任务。

复用节点需显示“复用任务 A 的结果”，并保留来源引用，不能显示为本次刚执行成功。
节点事件支持可选的 `execution: "reused"` 与来源引用，由脚本复核后上报；
通用状态仍表示该节点结果可用，UI 同时展示复用标记。脚本未确认复用时，应用不能凭计划自动标绿。

从节点重跑时，相关后续节点以待执行开始；原任务中的成功状态不能覆盖新任务的待执行状态。
新任务详情清楚区分“已停止”“失败”“本次执行完成”和“复用旧结果”。

## 兼容性和验收

| 场景 | 预期 |
| --- | --- |
| 旧动作不声明参数或续跑 | 点击方式、命令及事件行为保持兼容 |
| 选项由项目脚本枚举 worktree | 应用不调用 Git；中文和空格路径准确传递 |
| 初次参数预览后取消 | 不创建执行任务，不修改业务环境 |
| 检查和构建完成，部署中停止 | 本机停止完成后，可申请从部署节点继续 |
| 点击运行中的节点 | 可筛选日志，不能并发续跑 |
| 从部署继续，检查点及产物有效 | 复用前置结果，只执行脚本确认的部署及后续流程 |
| 从构建节点继续 | 重新构建并重新处理受影响下游，旧下游状态不直接继承 |
| 从部署后检查继续 | 脚本确认已部署身份后仅执行计划中的检查 |
| 原提交变化、产物被替换或检查点丢失 | 明确拒绝，提示可行起点；不自动更新版本或全量重跑 |
| 前次 SSH 取消但远端仍执行 | 脚本识别并拒绝或按其恢复协议处理，不并发覆盖 |
| 预览后产物变化 | 正式执行前脚本复核失败，停止本次续跑 |
| 续跑预览后取消、重复确认或运行期间重复点击 | 取消不创建任务；同一凭据只消费一次；保留并发限制 |
| 任务连续续跑、应用重启 | 完整恢复任务链、原始检查点归属及每次实际结果 |
| 旧任务未上报检查点 | 默认不能续跑，保留查看日志和重新运行 |
| Web 和桌面入口 | 共用参数、预览、节点操作与任务记录协议 |

## 实现范围

已实现通用能力及隔离示例：参数控件、脚本选项、预览确认、固定输入、检查点、节点续跑、关联历史、结果展示。
使用临时目录和模拟多阶段 Shell 验证恢复流程，不修改 Maikoo 业务脚本，也不执行服务器部署。

后续项目接入仅修改其自己的 JSON 与脚本。通用协议落地时同步 schema、AI_GUIDE、PROTOCOL、示例和安装包；
本文保留需求与设计依据；接入时以配套协议及业务指南为准。
